1. Data Minimisation

SentinelHealth collects only the minimum data required for workforce health surveillance: fatigue, heat exposure, shift details, symptom flags, and aggregated wearable metrics. No patient data, no diagnosis codes, no clinical records.

2. Anonymisation at Ingestion

Worker identity is hashed with HMAC-SHA256 using a server-side pepper before any database write. The raw worker ID never leaves the API process. Individual check-ins cannot be re-linked to a person without the pepper, which is held only by the platform operator.

3. Row-Level Security (RLS)

Every tenant-scoped table has FORCE ROW LEVEL SECURITY enabled. An officer in Mombasa cannot see Nairobi's data — enforced by PostgreSQL itself, not application code. The database refuses the query even if the API is compromised.

4. K-Anonymity (k ≥ 5)

Aggregated dashboards suppress any group with fewer than 5 reporters. A department × shift cell with 4 check-ins is mathematically invisible. This prevents identification by inference — even when combined with HR data, the numbers can't single out one person.

5. Append-Only Audit Trail

Every state change is recorded in a hash-chained audit table. Each row's hash includes the previous row's hash, so any tampering invalidates the chain. The application role has INSERT only — no UPDATE, no DELETE — for the audit table.

6. Right to Erasure

Workers may request deletion of their account at any time from their profile page. The system soft-deletes immediately (PII purged, account deactivated) and hard-deletes after the 30-day retention window required by Kenya's data protection regulations.

7. Regulatory Alignment

  • Kenya Digital Health Act (2023) — audit, encryption, access control
  • Digital Health (Health Information Management Procedures) Regulations (2025)
  • Kenya Data Protection Act (2019) — lawfulness, minimisation, accuracy
  • ISO 27799 — Health informatics security management
